Session Log

S1–S4 Foundation. PSPRecomp toolchain setup, ELF loader, stub scanner, basic HLE (threads, heap, I/O), guest memory layout.
S5 Init crash bypass. Traced 47 init function-pointer calls; fixed early crash in thread scheduler entry; init sequence completes.
S6 VRAM alias crash. canonical(0x4C000000)=0x0C000000 not covered by is_vram_window(); extended + remap_uncached_ram() for 0x0A000000 mirror.
S7 Task scheduler. CHAIN-BAD recovery; jump-table epilogue fix; null font guard; scheduler register save/restore; 0x0893346C and 0x08884040 treated as valid task exits. Frame 1 reaches display task; archive loads. Non-zero pixels still pending.
S8 GE pipeline root cause. Traced render chain timing (VCB path confirmed correct). Fixed GE vertex address range. Identified exact geometry blocker: ARCH-SYNTH returns fake entries with sub-chunk count=0, halting all vertex data writes. Root: archive object index table not populated despite main.bin loaded at 0x09644A80. Next: find + trigger archive init function.
S9 Scene discovery. Completed the init sequence, detected the Square Enix scene type 0x2713, and placed it on the guest pending-scene list. Activation and drawable GE commands were still missing.
S10 Real startup I/O. Rebuilt and visibly ran the native executable; real archives reached guest memory and the window presented guest VRAM without a host-side logo. GE execution remained state-only: no primitive, clear, or vertex-data commands.
S11 Cross-unit scene dispatch. Fixed the mixed-unit fallback so valid AOT targets are entered even when a unit also contains imports. The new build succeeds and reaches real MPK loading; the current blocker is malformed archive-record/object state before scene geometry is emitted. The authentic Square Enix logo remains unverified.
S12 MPK allocator tracing. Real embedded assets and the native framebuffer path are active. A large resource copy starts at guest address 0x08993940 and overlaps MPK table 0x089CC268, causing invalid archive sizes and zero drawable GE primitives. The allocator/free-list path remains to be corrected; no fake logo was added.
S13 PortableKit migration. Migrated the host runtime to PortableKit (same framework as the working Tenkaichi Tag Team port), replacing the custom HLE layer with its Vulkan renderer, kernel, GE state machine, and cooperative scheduler. The executable boots, loads the ELF, and registers 130 000+ AOT functions. sceKernelCreateThread and sceKernelStartThread route through PortableKit's kernel; the main game thread (uid=258) starts correctly. Previous blocker (invoke_chained_direct returning ctx.pc=0) resolved.
S14 Init sequence traced; interpreter crash. All 7 XUNIT init entries complete. Scheduler dispatches, archive loads, render loop reached. sceKernelStopModule HLE (PortableKit-internal) reads the module stop-function pointer 0x08BA77D0 and calls it. That address is in un-recompiled code (units 27–31 missing). Interpreter runs 72 801 instructions through the data section until it hits 0x0000FFFF at 0x08BEE950 — crash. NID override via rt.register_hle does not intercept the internal kernel call. Next: register 0x08BA77D0 as a no-op HLE stub so the interpreter never runs there.
S15 CHAIN-BAD root cause found; first GE display list enqueued. Root cause of every CHAIN-BAD crash identified: invoke_chained_direct fast path in runtime.hpp never pre-set ctx.pc before calling the target unit. All generated units dispatch via switch(ctx.pc) and ignore direct_entry_id — stale pc hit default: → ctx.pc=0. One line added in the fast path fixes all call sites systemically. First confirmed GE display list enqueued: [GE-ENQUEUE] list=0x09410180 — GRAPHICS::DlSendTask calling sceGeListEnQueue through the full recompiled chain. Current blocker: sceKernelStopModule → 0x08BA77D0 (un-recompiled) → interpreter hits 0x0000FFFF at 0x08BEE950. Fix: register 0x08BA77D0 as a no-op stub via rt.register_function.
S16 Init restart loop fixed; second route via 3rd Birthday's pipeline. PortableKit build: fixed the driver loop that re-entered the main entry on every unwind, the SPIN-BREAK hack that left the real main loop, an unbounded line rasteriser (the freeze), GE END handling and finish callbacks. Then ran D012 through 3rd Birthday's recompilation pipeline (generic runtime, real scheduler and GE; 3rd Birthday itself boots here from its own prepare flow). Found that the code generator only read the import table for PRX files, so all 296 D012 import stubs were no-ops; fixed the loader, entry point 0x08804040, $gp, 77 missing HLE imports, six VFPU ops, and recompiled the three runtime-swapped overlays (menu/battle/extra). The game now runs its real startup and enters the menu overlay. Still no splash: one thread spins on a semaphore without waiting for vblank, so the window never pumps (black, Not Responding).
S17 Renders on the 3rd Birthday route; native root cause found. The freeze was the runtime skipping its vblank tick when no vblank handler is registered (Dissidia polls vcount and the pad). Native build regenerated cleanly from the ISO executable with all imports bound to HLE. The generator dispatched on a stale ctx.pc after internal jumps, so returns landed on the wrong address; fixed to local_pc in the generator and all units. Added PPSSPP-hash texture replacement packed into the exe. Full rebuild pending; splash not yet confirmed natively.
